# TokenLens — 面向个人开发者的 AI 使用成本可视化与优化工具

> 产品概念报告 | 2026-08-13
> 灵感来源：rtk (75.8k⭐) + headroom (66k⭐) + CodeBurn + ccusage

---

## 一、产品概述

### 一句话概念

**让个人开发者像看手机流量一样看清 AI 花了多少钱、花在哪、怎么省——不只是一个仪表盘，而是一个帮你自动省钱的 AI 财务管家。**

### 核心问题

2026 年，AI 编程工具（Claude Code、Cursor、Codex、Gemini CLI 等）已经成为开发者日常基础设施。但几乎所有开发者都面临同一个困境：

- **不知道花了多少钱** — 各工具分散计费，Claude 订阅 + OpenAI API + Cursor Pro，月底一算吓一跳
- **不知道钱花在哪** — 今天跑了 50 个会话，哪个项目最烧钱？哪个任务本可以更便宜？
- **不知道怎么省** — rtk 能省 80% token，headroom 能压缩 92% context，但哪个适合我？怎么配？

### 为什么是现在

| 市场信号 | 数据 |
|---------|------|
| rtk GitHub Stars | 75.8k（Rust CLI 代理，节省 60-90% token） |
| headroom GitHub Stars | 66k（上下文压缩中间件，节省 47-92%） |
| CodeBurn 爆火 | 作者一周烧掉 $1400 后开源，追踪 16+ AI 编程工具 |
| ccusage | 12k⭐，最成熟的使用追踪 CLI |
| 企业 AI 支出 | 37% 企业年花费超 $250k（Kong 2025 调查） |
| Uber AI 预算 | 2026 全年预算前 4 个月用完 |
| 微软动作 | 取消内部 Claude Code 访问，转向自研 Copilot CLI |
| Headroom 累计节省 | 5 个月帮助用户省 70 万美元、2000 亿 token |

**结论**：「AI 使用成本优化」已经从隐性需求变成显性产品品类。140k+ stars 集中在两个项目上，说明市场需求巨大，但现有工具都是**单一功能点**（压缩 OR 追踪 OR 路由），没有一个是面向个人开发者的**全链路成本管家**。

### 2.2 关键竞品深度分析

#### rtk（Rust Token Killer）— 75.8k⭐

- **定位**：CLI 代理工具，拦截 AI 编程助手的 shell 命令输出并压缩
- **核心机制**：四层压缩（智能过滤 → 分组聚合 → 上下文截断 → 重复去重）
- **实测效果**：30 分钟 Claude Code 会话，token 从 11.8 万降到 2.39 万（省 80%）
- **优势**：Rust 单二进制文件，零依赖，<10ms 延迟，15 种 AI 工具支持
- **不足**：只优化命令输出，不处理代码文件、对话历史、RAG 片段；无可视化；无成本追踪

#### headroom — 66k⭐

- **定位**：上下文压缩中间件，Agent 和模型之间插一层
- **核心机制**：四引擎并行路由（SmartCrusher 处理 JSON / CodeCompressor 处理代码 / Kompress-base 处理日志 / CacheAligner 对齐 KV cache）
- **实测效果**：SRE 调试场景 65,694 token → 5,118 token（省 92%），准确率持平
- **亮点**：CCR（Content-Compressed Retrieval）可逆压缩；跨 Agent 共享记忆（SharedContext）；headroom learn 从失败 session 学习
- **不足**：四引擎配置复杂，面向团队而非个人；无可视化仪表盘；本地缓存持续增长无清理策略

#### CodeBurn — 2.3k⭐

- **定位**：本地 token 消耗成本仪表盘
- **核心能力**：解析 16 种 AI 编程工具本地日志，展示成本分解、趋势、异常会话
- **亮点**：UI 小清新好看；`codeburn optimize` 能发现浪费并给修复建议；`codeburn yield` 分析有效花费 vs 浪费花费
- **不足**：只追踪不优化；不支持实时干预；不集成压缩/路由能力

#### ccusage — 12k⭐

- **定位**：Claude Code/Codex 使用量追踪 CLI
- **优势**：最成熟、社区最大、MCP 集成
- **不足**：只支持 Claude Code + Codex；纯 CLI 无可视化界面；无优化能力

## 三、市场空白与机会

### 3.1 现有工具的三大断层

**断层一：追踪 ≠ 优化**

CodeBurn/ccusage 能告诉你花了多少钱，但不能帮你省钱。rtk/headroom 能帮你省钱，但不能告诉你省了多少。**没有人把「看见」和「优化」连成一条线。**

**断层二：团队级工具太重，个人级工具太轻**

LiteLLM/Langfuse 功能强大但配置复杂，面向团队。CodeBurn/ccusage 轻量但功能单一。**个人开发者需要的是「一键安装、自动发现、即时优化」的中间地带。**

**断层三：优化工具是碎片化的**

rtk 优化命令输出，headroom 压缩 context，LLMLingua 压缩 prompt，GPTCache 做缓存——开发者需要自己拼装 4-5 个工具。**没有人做统一编排层。**

### 3.2 产品机会

> **TokenLens = 成本可视化 + 优化编排 + 个人开发者优先**

核心差异化：不是再造一个压缩引擎或追踪工具，而是做**个人开发者的 AI 财务管家**——看见钱花在哪 → 告诉你怎么省 → 一键帮你省。

## 四、产品定义

### 4.1 目标用户

**核心用户画像**：独立开发者 / 自由职业程序员 / 小团队技术负责人

- **画像**：25-35 岁，每天使用 2-3 种 AI 编程工具（Claude Code + Cursor + Codex），月 AI 支出 $50-$500
- **行为特征**：同时维护 2-5 个项目，不同项目用不同 AI 工具组合
- **痛点**：月底发现 AI 账单远超预期，但不知道哪个项目/哪个工具/哪类任务最烧钱
- **场景**：打开仪表盘 → 看到本周花了 $87 → 发现 60% 花在 Claude Code 的代码搜索任务 → 一键开启 rtk 过滤 → 下周降到 $35

**用户规模**：全球独立开发者约 2500 万，其中使用 AI 编程工具的约 800 万，月花费 $50+ 的约 200 万

### 4.2 核心功能（5 个）

#### 功能 1：多源成本仪表盘（Cost Dashboard）

- 自动发现本地 AI 编程工具日志（Claude Code、Cursor、Codex、Gemini CLI、Copilot 等 16+）
- 按项目 / 工具 / 模型 / 任务类型 / 时间维度分解成本
- 实时趋势图：每日/周/月开销曲线
- 「烧钱热点」高亮：最贵的 5 个会话、浪费最多的操作类型
- **记忆点**：仪表盘顶部实时显示「今日已花 $X.XX」，像手机流量监控一样

#### 功能 2：浪费分析引擎（Waste Analyzer）

- 分析每个会话的 token 构成：有用 token vs 噪音 token（命令输出冗余、重复 context、过长日志）
- 计算每个会话的「有效收益率」(Yield Rate) = 有用 token / 总 token
- 自动识别浪费模式：
  - 重复读取同一文件（应缓存）
  - 简单任务用贵模型（应路由到便宜模型）
  - 命令输出未过滤（应用 rtk）
  - 对话历史过长未压缩（应用 headroom）
- 每条浪费都附带「一键修复」按钮

#### 功能 3：优化编排器（Optimize Orchestrator）

- 根据浪费分析结果，自动推荐并配置优化工具：
  - 检测到命令输出冗余 → 推荐安装 rtk → 一键配置
  - 检测到 context 膨胀 → 推荐安装 headroom → 一键配置
  - 检测到简单任务用贵模型 → 推荐模型路由规则
- 优化效果追踪：开启优化前后的成本对比图
- 优化配置管理：一个界面管理所有优化工具的开关和参数

#### 功能 4：预算守卫（Budget Guard）

- 设置月度/每日 AI 预算上限
- 预算消耗进度条 + 预测（按当前速率，本月预计花费 $X）
- 阈值预警：
  - 50%：提醒
  - 80%：警告 + 建议开启激进优化
  - 100%：自动降级（切换到便宜模型 / 暂停非关键 Agent）
- 异常检测：某个会话花费异常高时即时通知

#### 功能 5：成本对比与建议（Compare & Recommend）

- 模型性价比对比：同一任务在不同模型上的成本/质量对比
- 工具性价比对比：Claude Code vs Cursor vs Codex 在不同任务类型上的成本
- 个性化省钱建议：「你的代码搜索任务占 40% 开销，用 GPT-4o-mini 替代 Claude Sonnet 可省 70%，质量损失 <5%」
- 每周省钱报告：本周通过优化省了多少钱，还有多少优化空间

### 4.3 非目标（Non-goals）

- **不做团队级管理**：不做多用户、权限管理、审批流程——这是 LiteLLM/Langfuse 的领域
- **不做模型托管/代理**：不做 API 网关或模型代理服务——专注本地分析
- **不做新的压缩引擎**：不自研压缩算法，而是集成和编排 rtk/headroom 等现有工具
- **不做 AI 编程工具**：不替代 Claude Code/Cursor，是它们的「成本副驾」

## 五、设计方向建议

### 5.1 视觉风格

- **关键词**：Clean、Data-Driven、Trustworthy、Developer-Friendly
- **色调**：以深色科技蓝/青色为主色（#0F172A 背景 + #38BDF8 强调色），局部用绿色（省钱）和橙红色（超支）做语义色
- **参考产品**：Vercel Analytics 的数据可视化风格 + Raycast 的开发者工具质感 + Linear 的极简精确

### 5.2 交互亮点

1. **「烧钱温度计」**：仪表盘顶部一个横向温度计组件，实时显示当日花费进度，从绿色渐变到橙红色，一眼看出是否超支
2. **「省钱动效」**：开启优化工具后，数字从旧值动画滚动到新值（$87 → $35），配合绿色粒子效果，给用户即时的省钱正反馈
3. **「浪费气泡图」**：用气泡图展示各类 token 消耗占比，浪费的气泡用半透明+虚线边框表示，点击可展开详情
4. **「一键优化卡片」」：每条浪费分析结果都是一个卡片，左侧显示浪费金额，右侧一个绿色按钮「Fix now」，点击即自动配置优化

### 5.3 关键页面

| 页面 | 核心内容 | 设计重点 |
|------|---------|---------|
| Dashboard 总览 | 今日花费、本月累计、省钱总计、预算进度 | 信息密度高但不拥挤，核心数字大号显眼 |
| 会话分析 | 每个会话的 token 构成、有效收益率、浪费点 | 时间线 + 饼图组合，支持钻取 |
| 优化中心 | 已启用优化工具、优化效果对比、可用优化推荐 | Before/After 对比图，开关切换动效 |
| 预算管理 | 预算设置、消耗预测、历史趋势 | 温度计 + 预测曲线，超支区域红色高亮 |
| 模型对比 | 各模型性价比、任务适配度雷达图 | 雷达图 + 散点图（成本 vs 质量） |

| 层级 | 内容 | 价格 |
|------|------|------|
| **开源版** | 本地成本追踪 + 基础浪费分析 + rtk/headroom 集成 | 免费 |

- 开源版通过 GitHub 传播（参考 CodeBurn 爆火路径）

- 与 rtk/headroom 生态联动：互相推荐，形成「AI 成本优化生态」

## 十、总结

TokenLens 的核心价值主张：

> **你不需要成为 AI 成本专家，TokenLens 帮你看清、省下、持续优化——像手机流量管家一样简单。**

市场已经验证了「AI 成本优化」是真实需求（140k+ stars），但现有工具都是碎片化的单一功能点。TokenLens 的差异化在于：

1. **全链路**：追踪 → 分析 → 优化 → 验证，一个工具完成
2. **可视化优先**：不是 TUI 或 CLI，而是精美的 Web Dashboard
3. **编排而非替代**：不自研压缩引擎，而是智能编排 rtk/headroom 等现有工具
4. **个人开发者优先**：零配置、自动发现、一键优化

这个方向的设计空间非常充足——数据可视化、交互式仪表盘、开发者工具审美、Before/After 对比动效——是一个能在 2 周内产出完整且高质量作品集项目的理想选择。
