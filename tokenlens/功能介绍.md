# TokenLens 功能介绍

**让个人开发者像看手机流量一样，看清 AI 花了多少钱、花在哪、怎么省。**

TokenLens 不是又一个压缩引擎，也不是纯用量仪表盘。它把「看见」和「省下」接成一条线：追踪本地 AI 编程工具的花费 → 把钱切成有用 / 浪费 → 一键编排 rtk、headroom、模型路由 → 用前后对比证明省了多少。

面向独立开发者、自由职业者和小团队技术负责人。纯本地运行，日志不出这台机器。

## 核心闭环

打开就能感到产品在做什么：

1. **看见** — 本周花了多少，其中多少是噪音
2. **正在烧** — 哪一条会话此刻还在把测试日志送进模型
3. **切开** — 每一笔钱都分成有用 token 和浪费 token
4. **一键修** — 针对浪费模式开启对应工具，而不是再读一篇文档
5. **证明** — 数字落下、斜纹变短、预算预测从超支变成可控

Agent（Claude Code / Cursor / Codex / Gemini CLI）和模型（Sonnet、Opus、GPT-5…）分开记账。谁在跑、真正计费的是哪颗 LLM，不再混在一起。

---

## 1. 总览：本周的钱，怎么被切开

- **正在烧**：进行中的会话实时往上跳。斜纹变长，表示浪费正在发生，不是事后账单。
- **花费带**：黑色是有用 token，斜纹是噪音 / 重复 / 过长上下文。斜纹可点，直接进入对应会话。
- **一键开启 rtk**：针对本周最大的洞（Claude Code 未过滤的命令输出）。开启后，进行中的会话几乎不再涨；Claude Code 历史会话的斜纹收短；Cursor、Codex 不受影响。
- **会话切片**：每条会话用同一套「有用 | 浪费」表示，而不是只给一个总金额。

记忆点：钱上能看见废的是哪一段。

---

## 2. 会话：Agent 和模型分开看

开发者常把「用的哪个工具」和「用的哪个模型」说成一件事。TokenLens 把它们拆成两列。

- 按 **Agent** 筛：Claude Code、Cursor、Codex、Gemini CLI
- 按 **模型** 筛：Sonnet 4.5、Opus 4.1、GPT-5、Haiku 4.5…
- 点进一条，看花费、有效收益、token 构成（输入 / 输出 / 工具输出）、时间线
- 进行中的会话带「正在烧」状态；浪费主要来自工具输出时，详情里可以直接开 rtk

有效收益 = 有用 token / 全部 token。低于 40% 的会话会被标出来。

---

## 3. 优化：编排现有工具，不自研压缩

三个开关，对应三种浪费模式：

| 工具 | 解决什么 | 作用对象 | 本周大约能追回 |
|------|----------|----------|----------------|
| **rtk** | 命令输出未过滤 | Claude Code | $38 |
| **headroom** | 对话上下文过长 | 全部 Agent | $22 |
| **模型路由** | 简单任务走了贵模型 | Codex / Cursor | $11 |

拨开关，本周花费和浪费带当场重算。先开影响最大的，再开下一步。TokenLens 不代替这些工具，只负责发现、配置、验证。

---

## 4. 预算：超支前先降级

- 月上限（演示默认 $400）+ 已花 + 按当前速率的月末预测
- 预测超出上限时，进度条出现超支段
- 阈值：50% 提醒 → 80% 警告并建议开优化 → 100% 降级（简单任务改走 Haiku，暂停非关键 Agent）
- 单会话异常：花费远高于中位数时，链到那条会话
- 本月按 Agent 拆开：看清是哪个助手在烧预算

优化开关会写入本地，预算页的本周数字和月末预测跟着变。

---

## 明确不做

- 不做团队权限、审批、多租户（那是 LiteLLM / Langfuse）
- 不做 API 网关或模型代理
- 不自研压缩算法
- 不替代 Claude Code / Cursor，只做它们的成本副驾

---

## 一句话怎么讲

> 别人告诉你花了多少，或者告诉你怎么省，但没有人把这两件事接上。TokenLens 让你看见浪费长在哪一段钱上，然后一键把它关掉。
